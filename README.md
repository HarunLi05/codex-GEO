# GEO 在线方案工作台

公开仓库仅用于发布编辑器代码和通用模板。

在线使用：<https://harunli05.github.io/codex-GEO/>

内容助手：<https://harunli05.github.io/codex-GEO/assistant.html>。页面可独立使用；实际生成需要先[部署 Cloudflare Workers 生成服务](server/README.md)。

## 报告保存与隐私

- 在网页里编辑的客户资料、报告正文、方案列表和历史版本，仅保存在当前浏览器中，不会上传到 GitHub 或自动发布到网站。
- 保持原有网站地址和浏览器存储键不变，更新网站不会主动删除用户已经保存的本机方案。
- 需要交付时，通过“导出客户版”或“打印 / PDF”保存到电脑，再由用户自行发送。导出会移除编辑工具和本机方案列表。
- 通过“备份全部方案”和“导入备份”迁移本机数据；备份文件应自行妥善保存。
- 当前不提供账号、云端同步或多用户权限隔离。同一浏览器配置中的其他使用者可能访问本机记录；清除站点数据会删除本机记录。
- 不要把客户报告、PDF、备份或真实客户资料加入公开仓库、模板代码或提交历史。`.gitignore` 已排除常见报告与备份路径，但不代替发布前检查。

公开网站和分支只保留通用编辑功能，原先上传的报告及内置客户专版已移除，公开分支以干净的新历史发布。旧提交直链、托管缓存或已下载副本仍可能保留此前公开的内容，不能保证撤回。

## AI 内容助手

工作台右上角的“AI 内容助手”在新页面打开，方便对照检查、手动复制。填写企业基础资料、推广方向，以及已确认的服务范围、价格、周期和资源口径，再选择 DeepSeek 或 Gemini，生成覆盖整份方案的65项内容：客户资料与目标、服务内容与报价、首月与全期排期、工作说明与反馈。每个区域独立展示中文字段名、工作台填写位置及可编辑建议，逐项复制，不自动覆盖方案。

“生成整份方案”按四区依次请求模型，显示区域进度；失败或取消时保留已完成区域，可只重新生成当前区域。各区保留生成时的资料标识，修改资料后会提示结果过期。JSON复制或导出用于核对与保留配置，不是自动写入工作台的动作；导出使用手动调整后的内容，不静默混入其他客户或旧资料的区域。

- 点击生成时，输入的企业资料、推广方向、服务配置与补充约束会经用户配置的生成服务发送到所选模型。应只提交真实、可使用且适合交给该服务处理的资料。
- 模型 API 密钥只放在 Cloudflare 的 Secret 中，不能写进 GitHub、浏览器设置或公开代码。页面使用独立服务访问口令连接网关，口令至少16个字符，不是 GitHub 密码或模型密钥。
- 助手仅在浏览器中记住生成服务地址，不保存资料、访问口令或生成结果；刷新后需要重新连接，关闭前应复制需要的内容。助手不读取或修改工作台方案库。
- 模型缺失的资质、案例、履历和参数应明确标为待核实。结构校验通过不代表事实正确，销售仍须逐项核对。生成失败时保留上次结果，并提示核对客户与资料。
- 服务方、日期、周期、平台、服务范围和费用直接来自用户输入。价格不由模型另定，未填报价保持空白；数量和资源可注明为执行额度或成品交付，执行额度不等于同量确认稿件、成片或发布记录。月度数量、税费、投流、拍摄和全天回复等服务若未确认，不自动写成已包含。
- DeepSeek 默认模型为 `deepseek-chat`，Gemini 默认模型为 `gemini-flash-latest`，可在服务端配置。未配置密钥的模型会禁用，不自动改用另一家服务。

部署方式、三项 Secret 名称和接口说明见 [server/README.md](server/README.md)。代码发布与真实模型服务启用是独立步骤；实际可用性还取决于模型账号权限和额度。

## 使用

1. 在“我的方案”新建或选择客户方案。手机端通过“我的方案”按钮打开列表。
2. **客户资料**：以五组信息填写推广对象、目标客户、优先问题、真实依据与优势、希望承接的行动。后三组提供可点选预设词，可继续补充和修改；区域、问题清单与标准目标按需展开。预设默认不选中，不代表事实已核实或服务自动包含。
3. **服务安排**：在“服务内容与报价”中填写平台、服务项目与数量、费用等配置；“首月排期”按周明确工作与交付，“年度运营”明确全年阶段重点及每月计划、内容发布台账、监测问题、复盘安排；“工作说明”按需修改。
4. **预览与导出**：按章节查看客户版本，可返回对应栏目编辑。打印和客户版 HTML 共用 A4 排版：逐章测量，优先压缩间距，必要时适度缩放（最低90%）；超出可读范围时生成明确续页，保留所有文字并更新实际页码。

第一步的新客户资料默认为空，示例与提示仅作为占位文字；新建时主动填写的客户名称会保留。旧版本完全匹配系统示例的文字按未填写处理，实际客户资料与历史记录继续保留。可选服务目标不填时沿用报告标准目标，填写后替换，清空后恢复标准目标。

编辑自动保存在当前浏览器，无需下载后再打开。历史版本、手动留存节点及复制方案位于“更多操作”，备份和导入位于方案侧栏。

新增业务依据、承接行动和例外备注字段默认留空；业务信息以独立标签展示在报告中，不与标准段落拼成长句。服务范围、题材和承接方式仍需双方核实。核实注释保留在第1页和第4页，其他页脚仅显示客户名称、方案名与页码。

工作台不会按业务字段自动生成或填入观察问题：留空时仅显示待确认说明。可手动填写，或从内容助手核对后复制问题清单。专业性较强的业务建议主动展开此项，逐一核实问题中的术语和适用范围。

旧版已有的本机方案、字段和历史记录保持兼容；切换步骤不会丢失编辑内容。每个方案最多保留30个版本，恢复前的内容也会留存。存储失败会明确提示；其他标签页同时修改时暂停保存，避免覆盖。

服务周期会同步调整报告阶段表和对应正文编辑栏：13个月可显示至第13个月，短周期隐藏超出周期的阶段，未知周期明确标为参考。此联动仅调整阶段标题与显示范围，不改写已保存的正文和历史记录；自定义正文中的具体日期、节假日和周期表述仍需核对。

第6页末尾的服务对接说明固定为“服务对接：启动时确认服务对接人与联系方式。”，不再读取旧方案的 contact 字段；旧字段与历史资料仍保留，但不再作为可编辑输入或写入报告。内容核对安排仍独立填写。

第6页“服务清单与报价”用浅灰色块集中展示已有的服务项目与数量，并用较深灰底和加粗文字突出服务费用；预览、工作台 PDF 和客户版 HTML 打印共用此样式。费用支持多行填写报价、周期、含税口径和付款安排，留空仍不显示费用行。数据沿用原字段，旧方案不需要迁移。活动可自行写明常规数量、真实加赠及活动合计，并区分月度与全期、内容篇数与发布条次；系统不自动计算或添加活动、数量、报价。

## A4 打印

- 工作台“打印 / PDF”和导出客户版 HTML 使用相同的离线 A4 排版功能。
- PDF 设置建议：A4、纵向、缩放100%、边距无，并关闭浏览器自带页眉页脚；报告内已有独立页脚。
- 通常字量以六页模板排版。超过单页可读容量的内容按章节明确续页，不裁切文字、不用无限缩小字号硬塞六页。
- 打印只测量报告副本，不改动客户资料、方案正文及历史记录。客户版 HTML 内置的脚本仅负责离线打印排版，不读取浏览器方案库，不访问外部网络。
- “工作”“交付”“贵司配合”等旧版扁平标签会补齐中文冒号；原始历史记录不被改写。

## 开发与部署

静态网页，无需构建依赖。GitHub Pages 来源为 `main` 分支的 `/(root)`。

本地运行：`python -m http.server 8765 --bind 127.0.0.1`。

安装 Python Playwright 与 Chromium 后运行 `python tests/test_workspace.py`，验证本机保存、历史恢复、报告导出、编辑期间无网络请求，以及异常处理。另需 PyMuPDF（`fitz`）运行 `python tests/test_print_layout.py`，以真实 PDF 验证全部预设、长业务说明、手机打印、独立 HTML、续页文字完整性和实际页码。

`python tests/test_quote_pdf.py` 验证多行服务与报价保存、两种导出路径的灰色强调、费用留空隐藏、通常六页排版及超长清单续页完整性。

`python tests/test_service_period.py` 验证编辑器与助手的65个字段一致、13个月及短周期的真实PDF和客户HTML；`node --test tests/test_plan_schema.cjs` 验证共享字段结构、周期范围和已确认服务配置的处理。

`python tests/test_assistant.py` 验证双模型请求、逐项复制、错误和取消处理、手机布局、存储隔离；`node --test server/test/*.test.mjs` 验证模型网关及 Node 适配器。模型测试使用模拟服务，不调用真实 API。测试夹具为虚构业务信息，不含真实客户报告。

工作台编辑页面使用内容安全策略禁止连接远程接口，没有报告上传或自动同步功能。独立的内容助手页面仅在用户主动连接或生成时访问配置的服务。网站公开访问与报告在本机保存是两个独立范围。
